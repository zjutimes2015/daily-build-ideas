**One-line summary:** The #1 and #5 fastest-growing GitHub repos today are both "run a fleet of coding agents" consoles, and Product Hunt's weekly #1 is the same idea — build the quota, approvals, and result-comparison dashboard for agent fleets instead of yet another agent, and own the "manage the agents" entry point.

## Today's Build Idea: FleetWatch — "You run ten agents. Who's burning quota, who's waiting on you?"

**Product:** A quota and inbox console for coding-agent fleets. It doesn't write code and doesn't fight Orca or t3code for the editor slot. It does three things: collect every Claude Code / Codex / Cursor session across your machines into one inbox (who's waiting for approval, who finished, who failed); attach a quota meter to each session (used, remaining, reset time, warning before you hit the wall); and when the same task goes to multiple agents, show their diffs side by side so you pick a winner and merge. Approvals work from your phone.

**Who it's for:** Indie developers and small teams who have graduated from one agent to three-to-five parallel worktrees (the bottleneck is no longer model smarts, it's "I have no idea which session is stuck and which one burned my weekly quota"); heavy users running agents on their own subscriptions (quota is their own money); client teams who need agent usage accounted per project.

**Core features:**

1. Fleet inbox: aggregate session state across machines and harnesses — running / waiting for approval / done awaiting review / failed — one click to the worktree and diff, no more hunting through terminals.
2. Quota meters: usage by subscription, by project, and by task, with reset times; warn early when one task burns abnormally fast instead of discovering it at the rate limit.
3. Same-task comparison: when one issue goes to 2–3 agents, show diffs, test results, and elapsed time side by side; pick one to merge, archive the rest.
4. Phone approvals: when a session needs a human nod, push it to your phone; approve or send back with one line of feedback and keep the fleet moving away from your desk.
5. Weekly report: sessions run, quota burned, and PRs merged per project — for your own accounting and for client billing.

**Pricing:** Free local single-machine board (fleet inbox + quota meters); $19/month Pro (multi-machine aggregation, phone approvals, same-task comparison, quota warnings); $49/month Team (shared fleet, per-project cost split, report export). Cost math: it reads local session files and subscription usage endpoints; it resells no tokens and touches no model calls. You're selling "the fleet doesn't run away from you," not compute.

**Why it's a small-team opportunity:** Orca (142k stars) and t3code (82k stars) are both building full agent IDEs, and Hub sells "run 100 sessions like 5" on Product Hunt — everyone competes on running more. Nobody seriously builds "how do you manage them once they're running": who burned the quota, who's waiting on approval, which of three answers wins. Small teams have no platform engineer; when the fleet spins out, the fix is closing terminals and starting over. FleetWatch is only the management layer, so it sits on top of any harness without fighting anyone for the editor.

**Honest boundaries:** This is a management layer, not another agent — it can't make a single agent write better code, only keep a fleet from spinning out. It differs from Neon Review (11-20, a cloud PR review bot) and LocalLoop (11-22, a local single-agent desktop app): those solve "how one agent does the work," FleetWatch solves "how ten agents don't collide." Monetization is unproven: whether heavy users pay monthly for a board plus warnings is an open question, and if Orca or t3code ships quota meters free, the standalone space shrinks — measure real concurrent session counts on the free local tier before committing to a pricing shape. Quota data also depends on how open each harness's usage endpoints are; v1 must label which numbers are estimates.
