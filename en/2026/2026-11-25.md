**One-line summary:** A real Linux kernel has been compiled to WebAssembly — it boots to a shell in under a second and now runs GUI apps. Build a "turn any Linux app into a browser link" sharing service, and own the "one-click try it" entry point before this goes from demo to infrastructure.

## Today's Build Idea: BootLink — "Turn Any Linux App into a Browser Link"

**Product:** A zero-install, shareable Linux-environment service for the browser. A developer pastes a GitHub repo, a Nix flake, or a package name, and BootLink — built on unkernel (a real Linux kernel running in WebAssembly) — generates a shareable link. Anyone who opens it gets the full app running in their own browser tab: no Docker install, no environment setup, no server. The compute runs on the visitor's own machine.

**Who it's for:** Open-source authors (a "try it in your browser" button in the README, replacing the "install Docker, then read the docs" drop-off funnel); tutorial and documentation writers (readers click a link and land inside a real, pre-configured environment); interviewers and training providers (one link is a clean exam environment); support and customer-success teams ("open this link and you'll see the exact environment where I reproduce your bug").

**Core features:**

1. One-click link: paste a repo or package name, get a link in under a minute — it boots to a shell or a graphical desktop (unkernel's own description: boots to a shell in less than a second).
2. 300,000+ packages ready to go: built on the nixpkgs ecosystem trynix has already proven bootable — Firefox, GIMP, Python, opencode and other everyday programs run out of the box, no image-building required.
3. Embeddable: iframe and badge buttons for docs sites, READMEs, and tutorials — "Try in browser" becomes an entry point next to "Star."
4. Session tools: file upload/download, terminal sharing, snapshots — encode a configured environment's state into the link, so the next person opens the exact same scene.
5. Team plan: persistent workspaces, shared sessions, usage analytics — support teams can keep a "reproduction inbox" where every ticket maps to a launchable environment link.

**How it charges:** Free tier, 5 links/month, public sharing; $19/mo Pro (unlimited links, custom domain, usage stats, snapshots); $49/mo Team (shared workspaces, support reproduction inbox, seat management). Cost math: compute runs in the visitor's browser, so the server only handles the Wisp relay and image distribution — you're selling the convenience of "a link *is* the environment," not compute.

**Why a small team can win this:** Gitpod and Codespaces proved developers will pay for zero-config environments, but they're server-side, so cost scales linearly with users. StackBlitz's WebContainers proved "environments in the browser" can be a business — but it only covers Node.js. This time unkernel extends the same idea from Node to all of Linux — and unkernel and trynix are still just demos and dev tools. What's missing is a hosted sharing layer: one-click links, persistence, embed buttons, team workspaces. That's exactly the kind of packaging indie hackers do best. Build the sharing experience and the template library now; by the time the big vendors react, you're already the default answer for "send a link, try a Linux app."

**Honest limits:** The technology is 13 days old — the unkernel repo was created on 2026-11-12, GPL-2.0, and today it's a breakthrough demo rather than mature infrastructure. Networking goes through a Wisp relay (allow-listed), first loads must download images, and heavy workloads (big builds, GPU tasks) aren't practical in WASM yet. Persistence and cross-device resume aren't solved in the demo — version one must honestly label what runs and how fast. Monetization is also unproven: developers expect free trials, so paid plans have to land on team and support use cases — ship the free tier first, measure real usage, then decide how much to invest in Pro features.

## Why Now

- **On 2026-11-19, unkernel shipped.** A real Linux kernel compiled to WebAssembly, published by Pooya Parsa: boots to a shell in less than a second, 2–32x faster than qemu-wasm, with a Wayland graphical desktop, networking, and sound — Linux in the browser went from "it runs" to "it's usable" in one release.
- **On 2026-11-23, trynix proved the breadth.** Farid Zakaria's post "2035 came early" shows trynix.dev booting any of 300,000+ packages in nixpkgs — Firefox, GIMP, solitaire, voice, `curl` for the weather, all running in a browser tab.
- **The developer reaction today is the hottest story on the site:** #1 on Hacker News, 951 points / 362 comments (read at 08:27 CST, still rising — 952 points on re-check); #1 on Lobsters (90 score / 4 comments); the unkernel repo has 1,583 stars in 13 days; and a separate unkernel post on 2026-11-17 drew 219 points / 84 comments — this isn't a one-day spike, it's a week-long climb.
- **The gap is real:** unkernel is a kernel engine, trynix is a demo site — neither has a hosted sharing layer: no persistence, no one-click links, no embed buttons, no team workspaces. That gap is the indie opportunity.
- **Precedent:** every step toward zero-config environments has paid someone — Replit moved the IDE into the browser, StackBlitz moved Node into the browser; this time it's all of Linux. The window is right now: the engine shipped 6 days ago, and the big vendors haven't moved yet.
