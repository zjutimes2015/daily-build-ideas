# 每日 Build Idea 简报 · 2026-11-23

**一句话摘要：** 一项研究刚证明，你勾选的"零数据保留"只管得住第一跳——做一个给提示词埋金丝雀的检测服务，谁偷读、从哪条路由偷的，一清二楚，抢"AI 供应链泄漏"这个刚被引爆的头两周窗口。

## 今日 Build Idea：PromptCanary——"给提示词埋金丝雀，谁偷读一清二楚"

**产品：** 面向用 AI 网关 / 聚合器（OpenRouter、Vercel AI Gateway 等）调模型的团队：在提示词、agent 上下文和 API 载荷里埋入唯一的金丝雀密钥（假 AWS key、唯一 URL、DNS 名），一旦有人在不该出现的地方使用它，立刻告警，并定位是哪条路由、哪个供应商泄漏的。

**给谁用：** 把代码、客户资料、内部文档喂给 AI 的小团队；用便宜聚合器省钱、但不知道提示词最终流向哪里的开发者；合规要求严、却不得不用第三方模型的中小公司。

**核心功能：**

1. 一键埋点：往提示词或 agent 上下文里自动插入金丝雀（假密钥、唯一 URL、DNS 记录），不影响模型输出。
2. 泄漏监听：DNS、HTTP、AWS、Git、SSH 全套蜜罐，密钥一被试用就触发。
3. 归因报告：哪条路由、哪个供应商、哪次调用泄漏的——"泄漏跟着卖家走，不是跟着平台走"，报告直接点名。
4. 告警直达：Slack / 邮件 / webhook，密钥被试用几小时内就通知，不是等账单来了才发现。
5. 路由体检：定期对你常用的路由做金丝雀探针，告诉你哪条路由干净、哪条在偷读。

**怎么收费：** 免费版 10 个活跃金丝雀、1 个项目、邮件告警；$19/月 Pro（无限金丝雀、Slack 告警、归因报告）；$49/月团队版（多成员、API、SIEM 对接）。成本账：监听端就是几台蜜罐服务器，每月几美元——卖的是"知道谁偷了你的提示词"，不是算力。

**为什么是小团队的机会：** 大厂有自家安全团队慢慢做；小团队现在裸奔——他们用聚合器省下的每一分钱，都可能以泄漏的形式还回去。而检测这件事不需要大模型，只需要蜜罐 + 看板，一个人几周就能做出来。

**诚实边界：** 经典金丝雀早已存在（Thinkst Canarytokens，免费）——缺口是"提示词专用"：按路由归因、按调用归因、针对 LLM 载荷的埋点方式；检测只能事后发现，不能阻止泄漏——产品卖的是"知道"，不是"防住"；归因依赖金丝雀设计，狡猾的读取者可能只读不碰密钥，覆盖面不是 100%；和 11 月 19 日的 PatchCheck 是同一安全赛道的不同产品（漏洞暴露面检查 vs 提示词泄漏检测），别做成同一个东西。

## 为什么是现在

- **2026-11-19，Dragos 的 HD Moore（Metasploit 作者）公布了一项五个月的研究。** 2026 年 7–11 月，团队向常用 AI 服务发了约 200 万条提示词，每条带一个唯一的金丝雀密钥（真 AWS key、SSH 密码、唯一 URL / DNS 名、私有 git 引用），然后守着看谁用它。
- **至少 3 家 AI 服务商已被攻破。** 10 月下旬一个窗口里，几百个诱饵 AWS key 全被偷走，连服务商拒掉的请求也没放过；被盗密钥累计触发了数万次 AWS API 调用，几小时内就被试用、列 S3、开 Bedrock、建 IAM 用户。
- **"零数据保留"只管第一跳。** 某中国 AI 实验室的系统抓取了发往其模型的一半以上提示词里的秘密链接，其中明确标记了零数据保留 / 不收集的请求约占三分之二；经美国服务商转售的同一模型，触发的是同一个爬虫。
- **转售商不需要任何漏洞就能偷读。** 推理市场里最便宜的卖家只要打开请求日志，就能读走全部提示词——有人在家用宽带手动打开秘密链接、挨个猜用户名；同一模型换个卖家就没事，泄漏跟着卖家走。
- **账单已经出来了。** Railway 估计，被盗客户密钥在 10 月一波事件里刷出了约 74 万美元的未授权 AI 用量，最多波及 10 万个工作区（上限估计）；Wiz 统计 10 月至少 9 家 AI 开发者平台披露了同类事件，称为"Black October"。
- **报道原文直接给了产品定义。** Dragos 的建议里有一条："往 agent 上下文里埋自己的金丝雀，把任何一次使用当作安全事件处理。"——这就是产品的一句话。
- **合规顺风：** FTC 早在 2024 年 1 月就说过，替别人托管模型的公司如果在数据收集上误导客户，可能违法。
